Reglas de detección activas

¿Qué hace fraudulenta una transacción?

El sistema clasifica una transacción como anómala si viola al menos una regla activa del Rule Engine. Las reglas viven en MySQL y se pueden modificar sin reiniciar el sistema (patrón Strategy).

Ejemplos que el sistema detecta:

  • Matrícula de $9.000.000 → supera límite de $6M
  • Pago de nómina procesado a las 2am
  • Login desde IP 192.168.1.x (externa a UAN)
  • Usuario sys.batch con comportamiento automatizado

¿De dónde vienen las transacciones?

En producción vendrían del Sistema de Pagos UAN (externo), del módulo de nómina y del módulo de matrícula. Estos sistemas publican eventos en RabbitMQ usando protocolo AMQP con formato JSON.

En este simulador las transacciones las genera tú directamente desde la pestaña "Simular transacción".

¿De dónde vienen las alertas?

El Fraud Analysis Service crea una alerta por cada regla violada. La alerta se guarda en MySQL y se publica en la cola alerts.queue de RabbitMQ.

El Notification Service notifica al Admin (ALTO) o Analista (MEDIO). El Alert Query Service expone las alertas al dashboard vía REST+JWT.
